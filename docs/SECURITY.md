# Security

## Existing controls

- Passwords use Node.js `scrypt`; sessions use opaque random tokens stored by hash.
- Project and game mutations require authenticated ownership; project writes apply same-origin checks.
- SQLite queries use prepared statements and project artifacts use version checks and audit events.
- Game previews use a restricted iframe sandbox and a restrictive content security policy.
- Production readiness remains false in the canonical blueprint.

## Boundaries and gaps

There is no multi-tenant organization/RBAC system, production secret manager, isolated agent/code execution environment, provider credential storage, wallet integration, payment processing, or distributed rate limiting. No code generated by an agent is executed because no code-generation worker exists.

Prompts, project files, provider outputs, and future tool results must be treated as untrusted. Do not grant a catalog entry runtime permissions based on its description. Sensitive operations, external calls, financial transactions, and production deployment require explicit authorization, least privilege, audit records, and independent verification.

Security status is partial and does not constitute a production security review.
